# nerv — omni-channel AI studio

nerv — это студия, где **человек заказывает** задачу, а **потребительский ИИ
играет студию на полном коде и приносит готовый продукт**. Охват: личная
рабочая станция — арт-студия (≤ 10 человек). Периметр доверенный;
auth/authz/TLS — за скобками.

**Windows: поддержки нет, не было, не планируется и не будет. Идите на хуй.**

Работа строится не как «запрос → ответ», а как производство: заявка проходит
творческую песочницу, из топлива составляется композиция, упаковка в промпты,
генерация и приёмка. Подробности и принципы kb — в [`kb/README.md`](kb/README.md).

## Что это за система

Два пакета:

- **nerv-core** (Go) — тонкий демон, который оркестрирует установленные в
  системе инструменты генерации, гоняя их через GPU-планировщик, и отдаёт
  streamable-MCP эндпоинт. MCP — единственная поверхность (мост, не зависящий
  от языка).
- **nerv-gui** (TypeScript / React) — чистый MCP-клиент: чат с потребительским
  ИИ и под-агентами + нелинейная таблица композиции (React Flow).

Ключевая идея — **минимум кода, максимум использования системных инструментов**.
В ядре нет хардкода: всё — подключаемый `sh`-инструмент. Транспорт инструментов
— HTTP streamable MCP. данные текут **файлами**: задача называет свой файл
`output` (имя с расширением — дисциплина ИИ); поля инструмента, помеченные
`"file": true`, — его файлы-входные. Планировщик стартует задачу, когда все
нужные файлы существуют; задача, застрявшая на файлах, которых не появилось, —
fail. Инструменты обнаруживаются динамически из `tools/` и самодокументируются
через `--tool-info`.

## Что в этом релизе (skeleton)

Релиз — это **скелет ядра**: то, что можно взять и развивать.

```
.
├── README.md            # этот файл
├── Makefile             # build / test / vet / clean
├── .gitignore
├── src/
│   ├── nerv-core/       # Go-бекенд (источник демона)
│   └── nerv-gui/        # фронтенд (MCP-клиент)
├── tools/
│   ├── example/scene.sh # образец самодokumentируемого инструмента (шаблон)
│   └── _nerv.inc        # общие sh-хелперы (nerv_out / nerv_in / ...)
├── kb/
│   └── README.md        # принципы написания собственного варианта kb
```

## Что НЕ в этом релизе

Это авторское наполнение, которое отрывается отдельно:

- **мясо `tools/`** — реальные инструменты под конкретные бэкенды (SDXL, anima,
  moss, krea2, yue2, minimax и т.д.); в релизе только шаблон `example/scene.sh`
  и общие хелперы;
- **kb** — полные руководства (протоколы, cognitive-skills, prompt-guides,
  review, official-docs); в релизе только `kb/README.md` с принципами;
- **`lora-model-dir/`** — модели LoRA;
- **`artifactory/`** — репозиторий арт-проекта (генерируется в рантайме);
- **бинарник** — собирается из источника (`make build` → `bin/nerv-core`).

## Архитектура

```
               MCP (HTTP streamable, /mcp)
                        │
        ┌───────────────┴───────────────┐
        │          nerv-core (Go)        │
        │  tools-discovery · scheduler   │
        │  GPU-adapter · artifactory     │
        │  knowledgebase · mcp-surface   │
        └───────────────┬───────────────┘
                        │  NERV_<FIELD>, NERV_ARTIFACTORY_DIR
                        ▼
              tools/*.sh  (системные инструменты)
                        │
        ▼               ▼               ▼
  image backend   audio backend   video backend
```

Планировщик не сканирует `tools/` при старте — инструменты обнаруживаются по
запросу через единый `browse` (`root=tools`) и `--tool-info`. Никакая схема не
зашита в ядро: поверхность инструментов строится динамически. Изменения в
`tools/` подхватываются сразу, без перезапуска демона.

## Структура директорий (где что лежит)

Все пути конфигурируемы и привязаны к корню проекта (родителю `bin/`), а не к
`cwd`:

| Директория        | Назначение                                                        |
|-------------------|-------------------------------------------------------------------|
| `tools/`          | потребительские `sh`-инструменты (tool id = путь относительно `tools/`) |
| `kb/`             | база знаний                                                       |
| `lora-model-dir/` | модели LoRA                                                       |
| `artifactory/`    | репозиторий арт-проекта — playground ИИ; все выходы задач живут здесь |

Корень проекта определяется как родитель директории с бинарником
(`dirname(dirname(binary)`), поэтому демон идентичен независимо от того, из
кай директории он запущен.

## Установка и сборка

Требования: Go ≥ 1.26. Системные инструменты (бэкенды генерации) ставятся
отдельно — nerv их только вызывает.

```sh
cd src/nerv-core
make build   # → bin/nerv-core
make test    # гонит тесты
make vet     # go vet
make clean   # убирает бинарник
```

## Запуск

```sh
bin/nerv-core --port 9696
# MCP listening on http://127.0.0.1:9696/mcp
```

Поверхность — только MCP. Основные флаги (все пути привязаны к корню проекта;
абсолютные пути остаются как есть):

| Флаг                  | По умолчанию         | Назначение                                       |
|-----------------------|----------------------|--------------------------------------------------|
| `--tools`             | `tools`              | дерево потребительских sh-инструментов           |
| `--artifactory`       | `artifactory`        | репозиторий арт-проекта                          |
| `--kb`                | `kb`                 | база знаний                                      |
| `--lora-model-dir`    | `lora-model-dir`     | директория моделей LoRA                          |
| `--ai-url`            | `http://127.0.0.1:5000/v1` | OpenAI-совместимый провайдер (LLM-транспорт)  |
| `--llm-offload`       | `false`              | выгружать LLM по API провайдера, освобождая VRAM |
| `--gpu-visible-devices` | (все)              | ограничить пул GPU через CUDA_VISIBLE_DEVICES    |
| `--port`              | `9696`               | порт MCP HTTP                                    |
| `--max-output-chars`  | `32768`              | лимит символов в одном результате инструмента    |
| `--human-token`       | (env `NERV_HUMAN_TOKEN`) | секрет human-режима (заголовок `X-Nerv-Human`) |

Если GPU-бэкенда нет (например, CPU-хост без `nvidia-smi`), демон всё равно
запускается: инструменты обзора/LLM работают, GPU-задачи быстро fail с
«no free GPU slots».

## Как написать инструмент

Инструмент — это самодokumentирующий `sh`-скрипт. Демон вызывает его с
`--tool-info` по запросу (не при старте); блок `--tool-info` описывает
инструмент для построения схемы — **никакой логики генерации** в нём не должно
быть. Образец — [`tools/example/scene.sh`](tools/example/scene.sh).

Контракт планировщика ↔ sh:

- каждый параметр → переменная среды `NERV_<FIELD>` (имя в ВЕРХНИй регистр,
  не-алфавитно-цифровые → `_`; массивы через запятую);
- `output` — файл, который пишет задача; приходит как `NERV_OUTPUT` (относительно
  artifactory, **с расширением**);
- поля с `"file": true` — входные файлы задачи (относительно artifactory);
  планировщик ждёт их появления перед стартом — **данные текут файлами, грани
  зависимостей заявлять не нужно**;
- `NERV_ARTIFACTORY_DIR` — корень artifactory (абсолютный); скрипт сам
  склеивает `root + NERV_OUTPUT`;
- код выхода = статус задачи (0 = ok, ≠0 = fail). Выход 0 без созданного
  объявленного файла вывода — **fail** (планировщик проверяет существование
  файла);
- приватные параметры (`"private": true`) живут внутри скрипта: вид ИИ их
  тихо отбрасывает, поэтому скрипт должен сам ставить те же значения по
  умолчанию, что и в `--tool-info`.

Общие хелперы — [`tools/_nerv.inc`](tools/_nerv.inc):

- `nerv_out` — собирает путь вывода под корнем, создаёт родительскую директорию
  и **архивирует** уже существующий файл того же имени в `<name>.1`, `<name>.2`,
  … перед записью (так задача всегда получает точное имя, а старые артефакты не
  теряются);
- `nerv_in` — собирает абсолютный путь входного файла;
- `nerv_batch_fix` — чинит именовании батча у некоторых бэкендов.

Имя файла — дело ИИ: `output` — финальное имя на момент отправки. Свежесть — это
дисциплина именования: переделка даёт **новое** имя (или сначала удаляет
устаревший файл).

## kb: как написать свой вариант

База знаний — долговечная память студии. В релизе только
[`kb/README.md`](kb/README.md) — там принципы и устройство kb: что должно быть в
каждой папке (`cognitive-skills/`, `protocols/`, `prompt-guides/`, `review/`,
`official-docs/`) и как это наполнять. Скопируйте этот файл и растите kb под
свой инструментарий и свои модели.
