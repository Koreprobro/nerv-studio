# nerv-studio

**nerv** — омниканальная AI-студия. Человек — **клиент**, выдающий заказ;
**consumer-AI** — исполнитель, который проигрывает целую студию и выдаёт
готовый продукт. `nerv-core` — тонкий Go-демон посередине: оркестрирует
системные генерационные инструменты, крутит GPU-планировщик и обслуживает
единственный streamable MCP-эндпоинт. Масштаб: от личной рабочей станции до
небольшой студии — доверенный периметр, без авторизации, всё локально.

В этом репозитории — ядро: Go-демон и технический контракт (SPECS.md) с
примером конфигурации. Toolbox генераторов — собственность оператора и в
релиз не входит: подключается любой исполняемый `sh`, соблюдающий контракт
`--tool-info` (см. ниже). Веб-клиент (`nerv-gui`: AI-чат с суб-агентами +
нелинейная таблица композиции, чистый MCP-клиент) ещё не начат.

## Законы дизайна

- **Минимум кода, максимум системных инструментов.** Ядро ничего не
  зашивает: каждый генератор — подключаемый `sh`-скрипт, обнаруживаемый в
  рантайме через `--tool-info`. Обёртка над `sd-cli`, `ffmpeg`, `comfy-cli` —
  чем угодно — это скрипт, а не патч.
- **Хранилище — чистая конфигурация.** Карта `domains` в nerv.json монтирует
  произвольные директории как MCP-инструменты (`{path, commands, hint}`).
  Две команды — структурные гранты: `mount` помечает *playground* — единый
  корень io, дом для queue-файлов и HTTP-маунт `/artifacts`; `execute`
  помечает *toolbox*, в котором имена инструментов очереди разрешаются без
  поиска по чужим директориям. Встроенных корней нет.
- **MCP — единственная поверхность.** HTTP-streamable JSON-RPC на `/mcp`,
  раздача файлов на `/artifacts/<rel>`. `tools/list` генерируется из
  конфига: по инструменту на домен, затем утилиты (`dice.roll`,
  `calc.resolution`). Приватных каналов нет — студией может управлять
  любой MCP-клиент.
- **Данные текут через файлы.** Задача называет свой `io:"out"`-выход и
  стартует, когда все её `io:"in"`-входы есть на диске. Очередь — dataflow
  существования файлов: без графа и объявленных рёбер.
- **Демон владеет волнами.** Отправленная очередь доходит до конца внутри
  демона (async-волны переживают разрыв соединения), результат остаётся
  доступным по id волны, а старый файл с тем же именем уезжает в архив как
  `name-1.ext`.

## Быстрый старт

Требуется: Go (1.26+), POSIX `sh`; GPU и генерационные CLI — только если
запускать настоящие генераторы.

```sh
make build                      # -> bin/nerv-core
cp nerv.json.example nerv.json  # смонтируйте директории под свою машину
./bin/nerv-core                 # 127.0.0.1:9696  /mcp + /artifacts
curl -s localhost:9696/mcp -X POST -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Демон выводит корень проекта из собственного расположения (родитель `bin/`),
поэтому относительные пути доменов переживают любой стартовый cwd. Минимальный
`nerv.json` требует ровно один `mount`-домен; toolbox (ваша директория
sh-скриптов) — это грант `execute`:

```json
{
  "domains": {
    "tools":       { "path": "tools",        "commands": ["probe", "read", "execute"] },
    "artifactory": { "path": "/storage/out", "commands": ["browse", "probe", "read", "fetch", "write", "mount"] }
  }
}
```

## Запуск волны

Очередь — голый JSON-массив строк `{tool, params}`. Запишите её в playground
и запустите через toolbox:

```json
[ { "tool": "krea2", "params":
    { "prompt": "a lighthouse at dawn, low tide, 35 mm photograph",
      "width": 1888, "height": 1056,
      "output": "lighthouse/portrait.png" } } ]
```

`tools { "command": "execute", "queue": "lighthouse/queue.json" }` принимает
строки в работу (битая строка падает в `skipped` и не останавливает волну) и
выбирает режим:

- **async** (по умолчанию) — ответ с id волны возвращается сразу; волна
  принадлежит демону, разрыв соединения её не убивает.
- **blocking** — при `llm_offload: true` и любой строке с GPU: chat-LLM
  сначала вымывается из VRAM, запрос держится до конца волны
  (SSE `notifications/progress`, если у клиента есть progressToken).

`{ "command": "execute", "wave": "latest" }` (или id волны) отвечает живым
снимком или финальным результатом: задачи со `status` / `dur` / `slots`,
`outputs` с `artifactURL` и `archived`. Журнал хранит последние 32 волны.

## Свой инструмент

Положите исполняемый `.sh` в директорию toolbox с грантом `execute`.
Контракт:

- `--tool-info` отвечает JSON-интерфейсом (`summary` + `fields`);
  `io: "in"` / `io: "out"` помечают файловые параметры, `hidden: true`
  (с `default`) прячет ручку от потребителя;
- параметры приходят env-переменными `NERV_<FIELD>`; файловые пути `io` —
  **полные абсолютные в обе стороны**: контракт — пометка, а не имя;
- `gpu-require` / `gpu-backend` / `gpu-pin` потребляет планировщик, в env они
  не попадают (истина устройств — `CUDA_VISIBLE_DEVICES` и т.п.);
- exit 0 плюс наличие всех объявленных выходов означает «готово»; демон
  создаёт директорию выхода и архивирует старый файл с тем же именем до
  старта скрипта.
