# nerv-studio

**English version: [README.md](README.md)**

**nerv** — омниканальная AI-студия. Человек — **клиент**, выдающий заказ;
**consumer-AI** — исполнитель, который проигрывает целую студию и выдаёт
готовый продукт. `nerv-core` — тонкий Go-демон посередине: оркестрирует
системные генерационные инструменты, крутит GPU-планировщик и обслуживает
единственный streamable MCP-эндпоинт. Масштаб: от личной рабочей станции до
небольшой студии — доверенный периметр, без авторизации, всё локально.

В этом репозитории — ядро: Go-демон и технический контракт (SPECS.md) с
примером конфигурации. Toolbox генераторов — собственность оператора и в
релиз не входит: подключается любой исполняемый `sh`, соблюдающий контракт
`--tool-info` (см. ниже). Веб-клиент (`nerv-gui`: AI-чат с суб-агентами +
нелинейная таблица композиции, чистый MCP-клиент) ещё не начат.

## Законы дизайна

- **Минимум кода, максимум системных инструментов.** Ядро ничего не
  хардкодит: каждый генератор — подключаемый `sh`-скрипт, обнаруживаемый в
  рантайме через `--tool-info`. Обёртка `sd-cli`, `ffmpeg`, `comfy-cli` —
  чего угодно — это скрипт, а не патч.
- **Хранилище — чистая конфигурация.** Карта `domains` в nerv.json монтирует
  произвольные директории как MCP-инструменты (`{path, commands, hint}`).
  Две команды — структурные гранты: `mount` помечает *площадку* — единый
  io-корень, дом файлов очередей и HTTP-раздачи `/artifacts`; `execute`
  помечает *toolbox*, где резолвятся имена инструментов из очереди (без
  фолбэка между toolbox). Встроенных корней нет.
- **MCP — единственная поверхность.** HTTP-streamable JSON-RPC на `/mcp`,
  раздача файлов на `/artifacts/<rel>`. `tools/list` генерируется из конфига:
  по инструменту на домен, затем утилиты (`dice.roll`, `calc.resolution`).
  Приватных каналов нет — студию может вести любой MCP-клиент.
- **Данные текут через файлы.** Задание называет свой `io:"out"`-файл и
  стартует, когда все `io:"in"`-входы есть на диске. Очередь — dataflow
  существования файлов: ни графа, ни объявленных рёбер.
- **Волнами владеет демон.** Отправленная очередь доходит до конца внутри
  демона (async-волны переживают разрывы), результат доступен по id волны,
  а старый одноимённый выход архивируется рядом как `name-1.ext`.

## Быстрый старт

Требования: Go (1.26+), POSIX `sh`; GPU и генерационные CLI — только для
настоящих генераторов.

```sh
make build                      # -> bin/nerv-core
cp nerv.json.example nerv.json  # направьте домены на свою машину
./bin/nerv-core                 # 127.0.0.1:9696  /mcp + /artifacts
curl -s localhost:9696/mcp -X POST -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Демон выводит корень проекта из собственного расположения (родитель `bin/`),
поэтому относительные пути доменов переживают любой рабочий каталог запуска.
Минимальному `nerv.json` нужен ровно один `mount`-домен; toolbox (ваша
директория sh-скриптов) — грант `execute`.

## Конфигурация

Один файл, `<project-root>/nerv.json` (или `--config <path>`). Приоритет:
**явно переданный CLI-флаг > конфиг-файл > встроенный дефолт**. CLI принимает
оба написания (`--ai_url` и `--ai-url`); `--env KEY=VALUE` повторяем и
сливается поверх секции `env`. `debug` — только флаг (`--debug`): логи волн
живут во временной директории и сворачиваются в блок `wave` файла очереди.
Строгий JSON: игнорируется ровно ключ `_comment` (документирующие `_comment_*`
предупреждают один раз и сбрасываются).

| ключ | дефолт | роль |
|---|---|---|
| `domains` | — (обязательно) | вся поверхность хранилища; см. следующий раздел |
| `ai_url` | `http://127.0.0.1:5000/v1` | OpenAI-совместимый эндпоинт для смыва VRAM (ваш локальный `llama-server`) |
| `llm_offload` | `false` | VRAM-XOR: `true` = каждая загруженная чат-LLM выгружается перед волной с GPU-заданиями, и такие волны идут блокирующе; `false` = все волны async |
| `gpu_backend` | `""` (всё обнаруженное) | фильтр пула, термины `backend[@host][:i или a-b]`, напр. `cuda,rocm:0-1` |
| `external_gpu` | `""` | анонимные удалённые слоты `backend@host[:N]`, без детекта и health-check |
| `port` | `9696` | единая HTTP-поверхность (`/mcp` + `/artifacts`) |
| `max_output_chars` | `32768` | ограничитель объёма текста результатов; полный дамп отдаётся по `volume_ack=true` |
| `env` | `{}` | машинное окружение, подмешивается **как есть** в каждый запуск инструмента (кэши, треды, директории моделей); ключи `NERV_*` отбрасываются — префикс принадлежит контракту scheduler↔sh |
| `media` | встроенные | бюджеты контента в контекст потребителя (read/fetch): лимиты текста, форма превью картинок/аудио/видео |

На одноплатном воркстейшене `llm_offload: true` — переключатель, позволяющий
делить одну карту между генерацией и чатом: чат-модель освобождает VRAM на
время волны, и волна держит запрос (SSE-прогресс при progressToken у
клиента). Это *когнитивная* настройка не меньше, чем аппаратная — она решает,
может ли AI наблюдать собственную генерацию вживую.

## Домены: поверхность хранилища

Всё, что consumer-AI видит на диске, — запись домена:

```json
"<имя>": { "path": "<директория>", "commands": ["read", ...], "hint": "однострочное описание" }
```

- **`name`** *и есть* имя MCP-инструмента (`[A-Za-z0-9_.-]`, кроме
  зарезервированных) — слово, которое модель печатает и читает весь день.
  Именование — это проектирование словаря.
- **`path`** — абсолютный или относительно корня проекта (никогда не рабочий
  каталог запуска). Директория `mount`-домена создаётся на старте.
- **`commands`** — allow-list, который инструмент отвечает; запрещённая
  команда получает `isError` со списком доступных. `fullRawAccess: true`
  игнорирует allow-list целиком (люк, не норма).
- **`hint`** — попадает в `tools/list` дословно; для языковой модели это не
  украшение, а *первая строка инструкции* к домену.

Набор команд:

| команда | даёт |
|---|---|
| `browse` | листинг директории (один уровень или ограниченный рекурсив) |
| `probe` | метаданные: статистика файлов, размеры медиа, заголовки safetensors; в `execute`-toolbox — диалект `--tool-info` |
| `read` | ограниченное чтение текста/картинок с окнами строк/байтов |
| `fetch` | забрать байты файла (артефакта) в рабочую область |
| `write` | создание / перезапись / добавление текстовых файлов (директории — по завершающему `/`) |
| `mount` | **структурная:** это *та самая* площадка — io-штраф для заданий, дом очередей, HTTP-раздача `/artifacts`, родословная волн. Ровно один домен |
| `execute` | **структурная:** это *toolbox* — имена инструментов очереди резолвятся в `<path>/<tool>.sh`, волны запускаются отсюда. Ноль, один или много |

## Настройка среды под когнитивную парадигму

То, что consumer-AI считает о том, кто он *и* что может в вашей студии,
равно набору видимых инструментов, умноженному на их описания. nerv даёт три
органа управления — всё чистая конфигурация:

1. **Возможности — allow-list команд.** Гранты — ваша модель разрешений: в
   read-only библиотеку (`read`, `probe`) не напишешь карандашом; черновик-
   домен (`write`) без `browse` — почтовый ящик, а не шкаф. Стригите гранты
   под роль, которую назначаете, а не под файловую систему.
2. **Поведение — hint.** Хинт домена — самая дешёвая из существующих
   prompt-инженерий: «сначала прочитай README.md; каждый документ называет
   следующий шаг и файл для записи» превращает папку заметок в *процедуру*,
   которую AI проходит. Дисциплинарные конвенции живут тут же: «один чат =
   один проект = одна директория; сначала создай `<project>/`» — хинт
   площадки это несёт.
3. **Форма мира — какие домены существуют и как названы.** Имена доменов
   становятся существительными модели. Студия, разделяющая `kb` (гайды),
   `plots` (пространство письма) и `artifactory` (продукты), учит модель,
   что знать, чертить и производить — разные действия.

Отработанные парадигмы (все — просто nerv.json):

- **Минимальный генерационный стенд** — `tools` (execute) + одна
  смонтированная площадка. AI — оператор-практик: probe инструмента, запись
  очереди, fetch результата.
- **Управляемая студия (kb-прогулка).** Добавьте `kb` с `read`+`probe` и
  точкой входа README.md; цепочка гайдов (каждый документ называет следующий
  шаг и файл для записи) заставляет многофазные процессы — бриф → сценарий →
  кадры → сборка — управлять AI с диска, а не из памяти чата. Знание —
  файловое дерево, а не системный промпт.
- **Писчий стол.** `plots` с `read`+`write`+`browse` и вовсе без toolbox:
  чисто текстовая студия писчего агента (библии миров, персонажи, черновики).
  Ни GPU, ни волн — демон всё равно остаётся всем файловым API модели.
- **Библиотека против верстака.** Смонтируйте один корпус дважды с разными
  грантами: хранилище весов как `browse,probe,fetch` (снаружи его читают
  sh-скрипты; AI осматривает, но не правит) рядом с записываемой рабочей
  копией для экспериментов.
- **Мульти-toolbox.** Несколько `execute`-доменов (`image`, `video`, `media`)
  делят поверхность инструментов на явные комнаты: имена очередей резолвятся
  внутри одного toolbox, фолбэка между toolbox нет — AI выбирает комнату, а
  не глобальное пространство из 40 инструментов.
- **Тяжёлые пайплайны как очереди.** Поскольку волна — dataflow существования
  файлов внутри демона, когнитивный стиль *планируй на диске, гони async,
  смотри потом* доступен без строчки клиентского кода: записал очередь,
  выстрелил `execute`, думаешь дальше; опрос
  `{"command":"execute","wave":"latest"}` или `POST /wave/stop` (красная
  кнопка) — когда нужно.

Правила большого пальца: **гранты** — для позы безопасности, **хинты** — для
культуры, **имена** — для словаря, а `hidden`-поля инструментов (с дефолтами)
убирают ручки с глаз модели. Конфиг — партитура студии; AI её играет.

## Запуск волны

Очередь — простой JSON-массив строк `{tool, params}`. Запишите её в площадку
и запустите через toolbox:

```json
[ { "tool": "krea2", "params":
    { "prompt": "a lighthouse at dawn, low tide, 35 mm photograph",
      "width": 1888, "height": 1056,
      "output": "lighthouse/portrait.png" } } ]
```

`tools { "command": "execute", "queue": "lighthouse/queue.json" }` принимает
строки (плохая строка попадает в `skipped` и не останавливает волну) и
выбирает режим:

- **async** (по умолчанию) — ответ возвращается сразу с id волны; волна
  принадлежит демону, разрыв клиента её не убивает.
- **blocking** — при `llm_offload: true` и любой строке с GPU: чат-LLM
  сначала смывается из VRAM, запрос держится до конца волны
  (SSE `notifications/progress` при progressToken у клиента).

`{ "command": "execute", "wave": "latest" }` (или id волны) отвечает живой
снапшот или финальный результат: задания со `status` / `dur` / `slots`,
`outputs` с `artifactURL` и `archived`. С `--debug` лог волны сворачивается
в сам файл очереди как `wave.debug` — файл очереди становится полной записью
собственного прогона. Журнал хранит последние 32 волны.

## Свой инструмент

Положите исполняемый `.sh` в директорию toolbox (`execute`). Контракт:

- `--tool-info` отвечает JSON-интерфейсом (`summary` + `fields`);
  `io: "in"` / `io: "out"` помечают файловые параметры, `hidden: true` (с
  `default`) прячет ручку от потребителя;
- параметры приходят как env-переменные `NERV_<FIELD>`; пути `io`-файлов —
  **полные абсолютные в обе стороны** — контракт в пометке, а не в имени;
- `gpu-require` / `gpu-backend` / `gpu-pin` потребляет планировщик, они
  никогда не инжектятся (истина устройства — `CUDA_VISIBLE_DEVICES` и т.п.);
- exit 0 плюс все объявленные выходы на месте = done; ядро создаёт
  родительскую директорию выхода и архивирует одноимённый старый файл до
  старта скрипта.

Образец целиком — `tools/anima-aestetic.sh`.
